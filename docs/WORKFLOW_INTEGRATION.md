# 不依赖常驻聊天的工作室

## 已接入

- `tools/install_codex_skill.py` 把 `skills/ai-studio/SKILL.md` 安装到本机 Codex 用户技能目录，展开真实工作室与 Python 路径。全局 AGENTS 只增加带标记的短指针，保留原有内容并备份；重复安装更新同一段。若全局 override 会遮住它，先明确报错，不覆盖用户配置。
- 新 Codex 不需要旧对话：通过全局指针发现技能，技能指向真实源码、调用入口、状态和交接。不依赖搜索某个日期的聊天或手动贴提示词。仅限这台机器、这个 Codex 用户；迁移机器需重新安装并配置官方客户端。
- `bridge.py consult` 复用已验证的官方 DeepSeek 调用，答复、会话、工作目录和散列证据保存到统一 SQLite 账本。重复 key 取原结果；不会重新调用。失败结果需要核对，不盲目接力写入。
- `routing_rules` 让规划、验收、不同专长分别选人。显式顺序可覆盖模型推荐，仍检查实际可用性和额度。规划与验收使用分开的原生会话，减少同一对话的锚定效应；这不等于已经证明模型独立性或质量提升。
- 现有 Python 控制器负责排队、检查、预算、恢复和停机。它可以独立于聊天运行 `run --watch`，空闲时不调用模型；本次没有安装开机自启或启动常驻服务。机器休眠、关机或进程停止期间不会执行。

Codex 官方发现规则：[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[技能](https://learn.chatgpt.com/docs/build-skills)。当前本机目录沿用现有 `.codex/skills`；全局 AGENTS 指针同时提供显式发现路径。

## 建议的下一层：让任务和验收标准成为中心

真正有价值的改进是减少主脑工作量，而不是让某个模型永远管理其他模型。

1. **任务先形成合同。** 只包含目标、必要输入、允许修改的范围、验收方法、额度/时间上限。程序可以直接执行的检查和已知步骤不找 AI；已有计划可直接提交。
2. **临时聘请专家。** 规划时需要高能力模型，常规执行选择满足要求的低成本成员，验收由独立会话检查成果。某成员余额不足或不适合任务时换人；换人交付文件和证据，不转述全部聊天。
3. **按同类任务的真实结果调优。** 后续按任务类别记录首次验收通过率、返工次数、总耗时、真实用量与人工介入。先满足质量门槛，再比较时间/成本。不能用“模型自己说有信心”、进程退出码或跨币种的假百分比替代质量。
4. **少量有上限的探索。** 新成员只在低风险任务上试用；验收不合格才升级。不能让所有模型每次先投票、竞标或各做一遍，这通常额外花费额度。高风险任务可明确选择复核。
5. **记住证据，忘掉闲聊。** 所有人只拿本步骤需要的输入、依赖成果和失败原因。不同项目使用各自状态目录和检查配置，不能把工作室自己的测试当成任意项目的验收。

其中任务合同、预算/检查、证据交接、临时角色与配置路由已经有实现；基于历史质量的自动学习选人尚未实现。先积累真实待办数据，不凭几个模拟测试声称“最优路由”或量化提效。

## 当前限制

DeepSeek 的明确咨询可以直接调用；自动余额查询、强制只读工具策略和无人值守复杂工作还未验收，因此没有伪装成全自动成员。Opus 可否担任主脑取决于它的实际 CLI 登录和额度；桌面窗口打开不代表命令行就绪。Codex 计算机操作能力也只在确实接通对应工具时可用，普通脚本不会继承某次聊天的所有工具。

外部写入后失去回执必须核对，不能靠换模型掩盖结果不确定性。工作室目前只在本机维护，未推送 GitHub。
