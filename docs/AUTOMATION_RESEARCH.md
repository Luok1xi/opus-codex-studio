# 自动协作选型：以实际效率为准

核查日期：2026-10-13 至 2026-10-14。Owner 最新目标是提高现有工作的完成效率。跨模型派工、额度路由、会话恢复都已有项目实现，不能据此声称存在市场空白。

## 本次采用什么

继续直接调用已接入的 **Codex 官方 CLI / App Server、Claude 官方 headless CLI**，使用它们的工具执行和原生会话；工作室只负责跨成员交接、额度选择与验证。新增 `examples/efficient.bridge.json`：Opus 优先主脑，Codex 候补主脑使用 high，普通 Codex 执行成员使用 medium，同账号共用额度观察和失败冷却。复杂步骤可指定 `agent: codex-lead`。这是待真实任务比较的起点，不是“最优参数”结论。

本机 `bridge.local.json` 已应用该分工，并将本仓库的 unittest 与完整性检查接为普通命令。每次修改完成后，桥接器直接执行检查；没有必要再付出一次 AI 调用来仅仅敲测试命令。配置仅适用于本工作室源码，其他工作目录须配置其自身检查。安装、doctor、测试都不触发模型推理。

采用官方 [单次运行设置](https://learn.chatgpt.com/docs/developer-settings) 覆盖子进程的思考强度；不改用户全局设置。测试失败且修复预算已用完时跳过无效终审；只读返工保留原任务依赖和成员能力。保留检查与语义验收，不以减小提示词字符数冒充真实账单节省。

## 已有工具能做什么，还缺什么

以下是官方文档、源码与公开问题的核查，**未在本机安装并同题实跑所有竞争方案**。星数、宣传和单项测试数不用于排名。“不适合当前接入”不等于“做不到”。

| 方案 | 已有能力与证据 | 对当前工作流的决定 |
|---|---|---|
| [Codex App Server](https://learn.chatgpt.com/docs/app-server) / [Claude headless](https://code.claude.com/docs/en/headless) | 原生任务、结果、会话；Codex 提供额度读数。Claude 订阅额度观察的接口稳定性须单独看待 | 已直接接入。Codex 有本机真实成功任务证据；Claude 真实执行仍待登录后的验收 |
| [LangGraph](https://docs.langchain.com/oss/python/langgraph/persistence) | 持久化步骤、恢复、中断，适合明确的有状态图 | 更复杂的分支工作流优先评估它；当前不叠加第二套图引擎。恢复节点不保证外部操作只发生一次 |
| [Temporal](https://docs.temporal.io/activity-definition) | 长期可靠执行、重试和恢复；官方要求有副作用的 Activity 具备幂等性 | 多进程、长服务任务时优先考虑；当前单机 CLI 工作引入服务运维尚无收益证据 |
| [OpenHands SDK](https://github.com/OpenHands/software-agent-sdk) | 可组合代理、工具、会话持久化和模型配置 | 若其运行环境与工具满足任务，可直接作为执行成员；当前没有完成本机兼容性及同题成本验证，不宣称已接入 |
| [Windows Agent Orchestrator](https://github.com/DrDexter6000/windows-agent-orchestrator) | Windows 派工、生命周期管理、验证资料 | 与我们的想法明显重叠。其 [v0.2 记录](https://github.com/DrDexter6000/windows-agent-orchestrator/blob/main/docs/changelog-2026-10-01-v0.2.0.md) 同时记录未通过的真实可靠性门槛，说明单测数量不等于实用可靠性 |
| [ryder orchestrator](https://github.com/ryderderder/orchestrator/blob/main/docs/GUIDE.md) | 多 CLI、额度选择、工作目录和会话管理 | tmux/WSL 路径会增加当前 Windows 环境组件；文档或源码中的重新派发不能直接等同于中途无损接管 |
| [Hydra](https://github.com/jpdlr/hydra) | 桌面终端、后台派工与可观察会话 | 需要多人监看大量会话时可试用；累计用量和软预算并不等于官方账户实时剩余额度 |
| [ACP](https://agentclientprotocol.com/get-started/introduction) 与 [Claude adapter](https://github.com/agentclientprotocol/claude-agent-acp) | 已有统一代理通信、工具权限与界面事件协议 | 新客户端能用 ACP 时优先复用；当前两种原生适配已能派工，无需为了统一协议再包一层。是否可恢复会话取决于该实现声明的能力 |

## 为什么“自动执行”还不等于“交给它就办完”

1. **操作发生与回执到达是两件事。** 文件写完、消息发出之后，进程可能退出或额度耗尽。重试会重复产生结果。Temporal 明确区分活动完成记录和执行次数；我们的 SQLite 同样无法与任意外部系统组成一个事务。
2. **会话恢复有边界。** 恢复同一客户端创建的会话、向另一个提供方交接成果、接管用户已打开的桌面聊天，是三种不同能力。统一协议与 GUI 点击并不会自动打通全部三种。
3. **必须验证实际成果。** Anthropic 的 [长任务 harness 实验](https://www.anthropic.com/engineering/harness-design-long-running-apps) 已采用生成与独立评价分工，并指出评价器也要校准。增加成员、反复自评不必然提高效率。实验里不同作品的耗时/费用不能当作同题对比。
4. **账户状态不是可靠常量。** 未知额度不等于还有额度；订阅限制、认证状态与模型窗口可能不同。账户/授权和第三方接口故障必须保留明确状态，不能通过开新窗口绕过限制。
5. **长 GUI 链条会放大局部错误。** [OSWorld2](https://osworld-v2.xlang.ai/) 的长流程评估把部分进度与完整成功分开。其特定模型/设置的结果不能外推到所有桌面任务；我们尚未做同条件 GUI 验收。

[Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents) 已公开将主脑、执行环境和外置会话日志解耦。因此“主脑 + 桥 + 成员”是可以借鉴的架构，不能当作独创壁垒。[多代理失败研究](https://arxiv.org/abs/2503.13657) 也将问题分为系统设计、代理协同与验证终止，支持把注意力放在完整任务结果上。

公开问题应作测试线索：[LangGraph #9106](https://github.com/langchain-ai/langgraph/issues/9106) 报告了嵌套并行中断下兄弟节点副作用重复。我们没有复现该特定版本，不能据此判断当前框架普遍不可靠；但它提示必须检查实际副作用，而非只检查最终图状态。

## 对我们旧版的反例测试

此前的 41 项测试没有覆盖这些问题。先新增五个测试，旧实现五项均失败；然后修复根因，并补充边界与真实子进程退出测试。

| 故障场景 | 旧行为 | 当前行为 |
|---|---|---|
| 真正写入后返回额度不足 | 文件出现两次相同写入 | 只写一次，进入 needs-reconciliation，停止后续派工与自动返工 |
| 只读步骤执行中进程退出 | 整个任务留在 interrupted | 在恢复次数预算内续接，完成的前置步骤保留 |
| 成功回执已保存，任务状态未保存就退出 | 不使用已保存的成果 | 核对步骤尝试号与成果 SHA-256 后续接，仍须检查和验收 |
| 机械检查失败且没有修复预算 | 仍耗一次 AI 终审 | 直接记下失败证据；该夹具流程从两次模型调用变为一次 |
| 只读任务被驳回 | 返工被赋予写权限 | 保持只读、能力边界、依赖图，传入具体评审意见 |

额外覆盖旧尝试回执、成果缺失/篡改、未知写结果后不再派发独立步骤、多个不同专长的只读成员返工，以及检查阶段中断。普通检查命令也可能写入，因此检查中断不会无条件重跑。人工停止也不说明此前没有副作用。

这些是确定性测试成员和真实本地文件/子进程的结果，不是模型理解能力测试。原生成员的权限隔离依赖客户端；自定义适配器必须真实执行只读合同。当前恢复规则针对控制进程中断，未验证断电与整机存储故障。

## 用什么衡量接入是否值得

优先使用实际待办；少量重复同题，固定输入、目标、模型、权限与验收者，比较单代理、当前桥接、候选工具。计入搭建与人工搬运时间，记录完成率、墙钟耗时、提供方实际用量/缓存/费用、人工介入次数与返工次数。不要让三个方案同时修改同一份源码。

先覆盖代码修复、资料报告、需要明确确认的外部动作；再注入“动作前断开”“动作后回执前断开”“额度不足”“授权缺失”。完成率和结果质量不下降，且总耗时或人工介入确有改善，才启用新默认项。找不到公开同题比较，就保留未知；不把营销排名写进路由。

当前优先补的是可解释的恢复、现成测试命令接入和按角色配置原生思考强度。分布式服务、通用桌面接管、全套编排平台安装尚无当前任务收益证据，不列为本轮交付目标。
